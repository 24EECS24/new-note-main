# 04 · 常见坑与排错

> [!note] 本章回答的问题
> 代码报错 / 图像畸变 / 不渲染时，怎么快速定位并解决？
> 本章是**踩坑合集**，按"高频 → 低频"排列，画图前扫一眼能省大量时间。

---

## 坑 1（最高频）：平方用 `^` 导致负半轴畸变

### 现象

代码能编译，但图像**左右不对称、负半轴畸变**，或高度值明显离谱。

### 原因

TikZ 的数学引擎（pgfmath）里，幂运算符 `^` 的优先级**高于一元负号**：

$$
-1^2 = -(1^2) = -1 \quad(\text{而非 } 1)
$$

所以当 `\xx = -1` 时：

```latex
\xx^2  →  展开成 -1^2  →  算成 -1   （错了，本意是 1）
```

### 解决

**平方一律用乘法**：

```latex
% 错误
\xx^2    \yy^2
% 正确
\xx*\xx  \yy*\yy
```

> [!tip] 想用幂符号也可以
> 写成 `pow(\xx,2)` 或用括号 `(\xx)^2` 都能避开优先级坑。
> 但 `\xx*\xx` 最简洁、最不会忘。

## 坑 2：循环变量和 plot 自变量重名

### 现象

图像错乱、坐标展开异常，甚至整图渲染失败（broken image）。

### 原因

`\foreach \x in {...}` 里的 `\x`，和 `plot[..., variable=\x]` 里的 `\x` 是**同一个宏**，
两者互相覆盖，导致坐标算乱。

### 解决

给两个变量取**不同的名字**，并用 `variable=` 明确指定 plot 的自变量：

```latex
% 正确：外层循环叫 \xx，plot 自变量叫 \yy
\foreach \xx in {-2.5,-2,...,2.5}{
  \draw plot[domain=-2.5:2.5, variable=\yy]
    (\xx, \yy, {公式});
}
```

> [!warning] 经验提醒
> `\def\x1`、`\def\x2` 这种"数字后缀"命名也有坑：`\x1` 其实是宏 `\x` + 数字 `1`，
> 连续多个会互相覆盖。变量名一律用**纯字母**：`\xa`、`\xb`、`\xx`、`\yy`、`\ra`、`\an`。

## 坑 3：坐标里复杂公式没加花括号 `{}`

### 现象

解析报错，或者公式里的括号被当成坐标分隔符。

### 原因

坐标 `(x, y, z)` 用逗号分隔，公式里若含逗号/括号，解析器会混淆。

### 解决

**坐标里的数学表达式一律用 `{...}` 包起来**：

```latex
% 错误
(\xx, \yy, 5*(\xx*\xx+\yy*\yy)*exp(-(...)))
% 正确
(\xx, \yy, {5*(\xx*\xx+\yy*\yy)*exp(-(...))})
```

---

## 坑 4：乘号 `*` 被省略

### 现象

编译报错或算出奇怪值。

### 原因

TikZ 数学表达式里，乘号**不能省略**。`2x`、`5(x²+y²)` 这种数学简写它不认识。

### 解决

所有乘法显式写 `*`：

```latex
% 错误
5(\xx*\xx+\yy*\yy)     2\xx
% 正确
5*(\xx*\xx+\yy*\yy)    2*\xx
```

## 坑 5：三角函数角度单位（度 vs 弧度）

### 现象

图像周期完全不对，波形挤在一起或拉伸 57 倍。

### 原因

TikZ 的 `sin`、`cos`、`tan` **默认按角度（度）计算**，而数学里通常用弧度。

### 解决

给角度**显式标注 `r`**（表示弧度）：

```latex
% 错误：把 x 当成"度"
sin(\xx)
% 正确：把 x 当弧度
sin(\xx r)
```

> [!tip] 记忆
> `sin(\xx r)` 里的 `r` = radian（弧度）。没有 `r` 就是"度"。
> 反三角 `asin/acos/atan` 返回的是**度**，要转弧度需 `*pi/180`。

## 坑 6：中文节点文字导致整图不渲染

### 现象

把图里某个 `node` 的文字写成中文，整张图变成 broken image。

### 原因

TikZJax（Obsidian 里的 TikZ 渲染引擎）的字体集**不含中文字形**，找不到字形即失败。

### 解决

- 节点文字一律用**英文或纯数学符号**：`node[right]{$x$}` 可以，`node[right]{极大值}` 不行；
- 必须显示中文 → 改用 Obsidian 原生 **Mermaid**，或用图片。

---

## 坑 7：samples 过高导致渲染失败/卡顿

### 现象

`samples=500` 之类时，图像渲染失败或非常卡。

### 原因

采样点过多，计算量过大，渲染引擎扛不住。

### 解决

- `samples` 常用 **50 左右**，光滑度足够；
- 特别精细的图用 100~200，**不要无脑上千**。

---

## 坑 8：domain 里包含奇点（如除零、对数负值）

### 现象

`1/x`、`ln(x)`、`sin(1/x)` 等在奇点附近报错或画爆。

### 解决

让 `domain` **避开奇点**：

```latex
% 画 sin(1/x)，避开 x=0
plot[domain=-1:-0.02] ...   % 只画负半段
plot[domain=0.02:1] ...     % 只画正半段
```

---

## 坑 9：`\def` 复合算术宏不可靠

### 现象

用 `\def\fxi{0.1*(\xi-1)*...}` 定义复杂算式宏，再在坐标里引用，结果 broken image。

### 解决

- **不要在 `\def` 里塞复合算术**；
- 把算式**直接写进坐标的 `{...}` 里**（像本笔记所有示例那样）；
- 需要预计算时，用 `\pgfmathsetmacro` 或直接算好写死数值。

---

## 排错快速决策表

| 症状 | 先查 |
|------|------|
| 整图不渲染（broken image） | 中文节点？`\def` 宏？samples 过高？奇点？ |
| 能渲染但图像畸变/不对称 | 平方是否用 `\xx^2`（改 `\xx*\xx`）？ |
| 坐标错乱 | 变量是否重名？`variable=` 是否写对？ |
| 报解析错误 | 公式是否加 `{}`？乘号 `*` 是否省略？ |
| 三角函数形状不对 | 是否写 `(\xx r)` 转弧度？ |

---

## 一句话总结

画三维函数图最常见的错误就三类：**负号优先级（平方用乘法）、变量重名、中文/宏/samples 导致渲染失败**。
记住：**平方写 `\xx*\xx`，两族线变量不重名，公式包花括号，乘号不省略，角度带 `r`**，就能避开 90% 的坑。
